# 交付前质量门槛

## 1. 先核查内容，再核查美观

- [ ] 客户目标、受众决策、范围与不包含事项明确，没有把旧案例原封不动复制成新客户方案。
- [ ] 三点论贯通全文，分析页Action Title有证据或明确的假设标识；导航页不强行写结论。
- [ ] 核心问题与初步思考、方法、工作流、Owner、交付物、客户输入、检查点逐一可对应。
- [ ] 工作计划体现并行/依赖与资源限制；初级研究的对象、方法、样本与可行性有依据。
- [ ] 商务条款、排期、量化价值与CV未虚构；案例相关且允许展示；样例标脱敏/示意。

## 2. 图形语义与图标

- [ ] 页面关系明确，主结构符合关系；并列不乱画因果箭头，二维矩阵有真实定义的两条轴。
- [ ] 有数量含义的大小、位置、面积与几何可计算复核；无数量含义明确示意。
- [ ] 图标帮助对象识别而非情绪装饰；数据/条款页可以完全无图标。
- [ ] 一页同层图标统一家族、填充方式、视觉重量、底板、色义与对齐；不能线性/卡通/立体混用。
- [ ] 图标配文字标签；移去图标仍然可读；复杂图标缩小后仍可辨认，且不遮挡数值、图例或连接线。
- [ ] 通用头像只表角色，实人姓名/职务/照片已经核实与授权；不把人物数量或图标大小暗示为指标。
- [ ] 原始素材未未经允许公开发布；图标来源与再分发许可明确。

## 3. 品牌、排版与证据

- [ ] 使用客户要求的品牌或模板；咨询公司启发预设不是官方规范，不能冒充官方交付物。
- [ ] 深蓝/酒红/炭灰等颜色克制；德勤启发风格黑/蓝灰为主、绿只点缀。状态色有文字或形状备份。
- [ ] 字体适配中文和可编辑目标，层级统一；不机械要求衬线标题、15字、60%内容面积。
- [ ] 每个真实数字和事实都有可定位来源/日期/版本；预测/假设有边界；示意不混入真实结论。
- [ ] 百分比/百分点、转化率/留存率、金额单位与期间一致；漏斗同群体同口径，桥接相加能回到终值。
- [ ] 在实际页面上检查可读性、字体替代、错位、溢出、图标裁切、遮挡；不能用机器简报检查替代渲染检查。

## 4. 机器检查与人工审查分工

执行`lint_slide_brief.py`检查简报字段、来源声明、图标意图、比例声明和工作流字段；运行`test_lint_slide_brief.py`检验脚本回归。脚本不联网，不解析PPT，也不证明来源可信、MECE成立、图标视觉一致或幻灯片可编辑。对警告逐条做人工判断，不能把“0错误”翻译成“咨询质量自动满分”。

标准Skill校验只检查技能结构与frontmatter，不证明教学材料已学习或规则有效。更新后另核对所有引用文件与版本号，并至少用一个有图标案例和一个无图标案例试跑。

## 5. 失败处理

先记录具体失败页/字段/来源，再修复对应规则或页面，重跑相关检查；避免为了过检移除所有复杂内容。无法确认的数据或权限问题保留为待确认，不冒充完成。GitHub推送后比较远端commit与本地commit；只有一致才声称已同步。
