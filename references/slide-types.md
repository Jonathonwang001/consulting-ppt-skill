# 幻灯片类型：结构选项而非固定模板

先按场景和阅读任务选择主表达，需要关系图时读`content-visual-grammar.md`。以下保留原版本的11种常用类型；组合证据参见`composite-visual-evidence.md`，组件参见`visual-modules.md`。字体/配色由获批领导/客户模板统筹，不随页型换样式。

| 类型 | 核心任务与结构 | 商务图标的适时角色 | 必须检查 |
|---|---|---|---|
| 封面 Cover | 客户目标导向项目名、客户/机构、日期、版本、适用保密级别 | 通常不用；客户logo需授权，场景图需相关 | 不使用未授权咨询公司标识，不把通用场景当客户实景 |
| 议程 Agenda | 2–6个章节/讨论问题，编号与阅读顺序 | 章节类别识别可选，数字导航常已足够 | 不把并列议程画成时间承诺，不强制Action Title |
| 过渡 Divider | 章节名/编号与本节问题，调节阅读节奏 | 通常不需要，避免装饰人物 | 短报告可省略；白底或单色，避免花哨渐变 |
| 问题树 Issue Tree | 核心问题→同标准分支→可验证子问题 | 顶层业务对象可用，叶节点以文字为主 | MECE靠内容核验，不靠贴“MECE”字样；连接线表达分解，不自动表达因果 |
| 工作计划 Gantt | 时间×工作流/事项、阶段、依赖、Owner和节点 | 阶段/交付物导航可选，数据表优先 | 时间尺度与并行真实；Proposal研究补客户输入/交付验收，内部动作补状态/风险/节点；未确认排期明示 |
| 现状—目标 Comparison | 同一维度对齐双栏/三栏，保留口径 | 两侧同一实体使用相同图标；不强制红叉绿勾 | 目标是已承诺、假设还是愿景？差距与措施分别说明 |
| 数据图表 Data Chart | 标题结论、原生图表、单位/期间/来源，必要的业务含义 | 通常不用；精确标签优于装饰 | 图形选择符合比较目的；来源可定位；Key Message Box不遮挡、不重复 |
| 二维矩阵 Matrix | 明确定义两条轴，数据点/方案与象限阈值 | 大多用直接标签，无须每点加图标 | 评分依据、权重/阈值可解释；有第三维才让气泡面积映射数量 |
| 漏斗 Funnel | 同群体同时间窗逐级转化，数值/分母、阶段转化率 | 阶段对象辅助可选 | 无真实比例则等宽阶段+数字并标不按比例；65%→38%是27个百分点，不是阶段转化率 |
| 逻辑路径 Arrow Logic | 顺序、依赖或有证据的驱动链，3–5步只是可读性启发 | 活动识别，如访谈/分析/交付；不强制每步配图标 | 明确箭头语义；并列杠杆不能被画成因果链 |
| 结论与行动 Conclusion | 关键判断、支撑、下一步责任与时限 | 行动对象分类可选，无图标也可成立 | 不强求恰好3条，行动可执行，未经证实的收益不写成保证 |

## 页面节奏与密度

高管摘要突出业务含义；分析页保留足够证据；方法/执行页展示闭环；支撑页承载详细口径。字号、留白和要点数量依阅读场景调节，不把15字/5条/60%写成硬指标。

一页有一个主要阅读任务，可有多个协调证据模块及不同子关系；例如价值链+环节数据、机制+趋势/对标。每块解释其证据贡献，不加无关矩阵填充。单模块足够时不强复合，全部版式依零溢出契约验收。

## 默认视觉策略

优先白底、清晰标题、少量主色重点与中性灰辅助；封面/过渡可以单色深底。衬线字体、金线、绿色人物等不是机构官方风格或咨询级必备元素。读取`business-icon-system.md`选择实体图标并保持风格一致。
