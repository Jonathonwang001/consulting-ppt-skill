# Proposal 撰写规范

本文档融合顶级咨询公司（麦肯锡、罗兰贝格、德勤）的Proposal写作规范，以及高质量项目建议书的实战标准。

---

## 一、Proposal 的本质定位

Proposal 不是能力展示，而是**解决客户问题的方案书**。客户读完后应该感受到：
1. 你深刻理解了我的处境和挑战
2. 你有清晰可行的解决路径
3. 你是完成这件事最合适的团队

**核心写作原则**：站在客户角度写，而非站在顾问角度写。每一页问自己："这对客户有什么意义？"

---

## 二、标准 Proposal 结构（High-Profile 版本）

### 模块1：Executive Summary（执行摘要）
**位置**：紧接封面，1页
**内容**：
- 客户面临的核心挑战（1-2句）
- 我们的解决方案框架（3点）
- 预期价值/成果（量化）
- 工作范围和时间线（简述）

**写作要点**：高管只看这一页就能做决策。必须独立成章，逻辑自洽。

### 模块2：背景与挑战理解（Context & Challenge）
**页数**：2-3页
**内容结构**：
```
现状描述（Situation）
  ↓
复杂化因素（Complication）
  ↓
核心问题（Key Question）
```
**写作要点**：
- 用客户自己的语言描述问题，体现深度调研
- 数据支撑现状描述（行业数据、客户数据）
- 明确指出"如果不解决，会发生什么"（紧迫性）

### 模块3：解决方案框架（Solution Framework）
**页数**：3-4页
**内容结构**：
- 解决方案总览（一张逻辑图）
- 各模块详细说明
- 方法论和工具介绍
- 预期成果和价值量化

**写作要点**：
- 方案要有层次感：战略层 → 策略层 → 执行层
- 每个模块说清楚"做什么"和"为什么这样做"
- 量化价值：节省X%成本、提升Y%效率、增加Z亿收入

### 模块4：工作计划（Work Plan）
**页数**：1-2页
**内容**：
- 分阶段甘特图（3-4个阶段）
- 每阶段的关键活动和交付物
- 里程碑节点
- 客户参与要求（需要客户配合的事项）

### 模块5：团队介绍（Team）
**页数**：1-2页
**内容**：
- 项目负责人（Partner/Director级）：照片+简历要点+相关经验
- 核心团队成员：职级+专长+相关项目
- 相关成功案例（2-3个，脱敏处理）

### 模块6：为什么选择我们（Why Us）
**页数**：1页
**内容**：
- 差异化能力（3点，具体而非泛泛）
- 相关行业深度
- 独特方法论或工具
- 成功案例量化成果

## 三、高质量 Proposal 的写作标准

### 标题写作（Action Title）
每页标题必须是**完整的结论性句子**，而非描述性短语。

| 类型 | 示例 |
|------|------|
| ❌ 描述性 | 市场分析 |
| ❌ 描述性 | 竞争格局概述 |
| ✅ 结论性 | 目标市场规模达800亿，但竞争格局高度分散，存在整合机会 |
| ✅ 结论性 | 三大竞争对手均缺乏数字化能力，为客户提供18个月先发窗口 |

### 数据使用规范
- 所有数据必须标注来源和年份
- 优先使用第三方权威数据（行业报告、政府统计）
- 客户内部数据需标注"客户提供"
- 预测数据需标注假设条件
- 禁止使用无来源的"约"、"大约"、"估计"等模糊表述

### 图表使用规范
- 每张图表必须有一个关键洞察标注（Key Message Box）
- 图表标题即结论，不是图表描述
- 图表颜色不超过4种
- 禁止使用3D图表（显得不专业）
- 饼图不超过5个扇区，超过合并为"其他"

### 文字精简规范
- 每个要点不超过15个字（中文）
- 禁止使用"我们认为"、"我们相信"等主观表述
- 用数字代替形容词（"显著提升" → "提升35%"）
- 禁止使用行话堆砌（除非客户行业通用）

## 四、不同类型 Proposal 的差异

### 战略规划类
- 重点：市场机会分析 + 战略选项对比 + 实施路线图
- 关键框架：3C分析、波特五力、安索夫矩阵、BCG矩阵
- 页数：12-20页
- 语气：宏观视野，长远布局

### 运营改善类
- 重点：现状诊断 + 问题根因分析 + 改善方案 + 价值量化
- 关键框架：价值链分析、流程图、根因分析（鱼骨图）
- 页数：10-15页
- 语气：务实具体，量化导向

### 数字化转型类
- 重点：数字化成熟度评估 + 技术路线图 + 变革管理
- 关键框架：数字化成熟度模型、技术架构图、变革管理曲线
- 页数：15-25页
- 语气：前瞻性，技术与业务并重

### 市场进入类
- 重点：市场规模（TAM/SAM/SOM）+ 竞争格局 + 进入策略
- 关键框架：市场细分、竞争对手矩阵、客户旅程地图
- 页数：10-15页
- 语气：机会导向，风险意识

## 五、常见错误与避免方法

| 常见错误 | 正确做法 |
|----------|----------|
| 标题是描述性短语 | 标题写完整结论句 |
| 一页塞太多内容 | 每页只讲一个核心观点 |
| 图表无洞察标注 | 每图必配Key Message Box |
| 数据无来源 | 所有数据标注来源和年份 |
| 方案过于泛泛 | 具体到可执行的行动项 |
| 过度使用项目符号 | 结构化段落+精简要点 |
| 忽视客户参与 | 明确说明需要客户配合的事项 |
| 价值无法量化 | 用具体数字表达预期成果 |
| 团队介绍流于形式 | 强调与本项目相关的具体经验 |
| 保密条款缺失 | 每页底部标注保密级别 |

## 六、Proposal 审查清单

提交前逐项检查：

**内容层面**
- [ ] Executive Summary 独立成章，逻辑自洽
- [ ] 每页标题是Action Title（结论性句子）
- [ ] 所有数据有来源标注
- [ ] 解决方案有量化价值
- [ ] 工作计划有具体里程碑
- [ ] 说明了客户需要配合的事项

**视觉层面**
- [ ] 配色统一，不超过4种颜色
- [ ] 字体统一（标题Serif，正文Sans-serif）
- [ ] 每页有页码和保密标注
- [ ] 图表有Key Message Box
- [ ] 留白充足，不拥挤

**逻辑层面**
- [ ] 整体符合金字塔原理（结论先行）
- [ ] 问题树满足MECE原则
- [ ] 解决方案与问题一一对应
- [ ] 从现状到方案有清晰的逻辑链
