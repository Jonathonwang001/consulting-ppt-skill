# 故事线与逐页设计简报

## 1. 项目级输入

```markdown
# [项目名称] — [受众/机构] — [日期/版本]
- 场景：[external_proposal/internal_executive/internal_working/mixed]
- 阅读者：[职责/已有知识/时间；理解/决定/监督/讨论]
- 阅读方式：[现场讲述/会前自主阅读/专业核对]
- 主要任务：[需要读者获得的认识/决定；没有待决定事项也有效]
- 范围/不包含：[业务/地域/期间/责任边界]
- 已批准参考：[领导/客户认可的模板、框架、图表与图片；版本及许可]
- 交付：[内容草稿/可编辑PPT；默认一个完整主稿]
- 证据清单：[真实数据/公开资料/访谈/项目方主张/信息缺口]
- 排版契约：[字体/字号角色/网格/边距/内边距/标签安全区；零溢出]
- 故事线：[执行摘要→实质章节及小结→建议/关注项→同稿支撑索引]
```

## 2. 场景决定闭环

Proposal研究采用目标→问题ID→假设/缺口→验证方法→工作流/Owner→交付物→客户输入→检查点。内部进度/行动采用事项→状态/差距→原因/风险→Owner→下一节点；内部纯诊断页无需强加客户输入、研究工作流或待批准事项。

| 内部事项 | 当前状态/差距 | 证据与风险 | 责任/未决角色 | 下一节点 |
|---|---|---|---|---|
| [具体事项] | [实质完成状态] | [依据/反证/局限] | [已核实或待确认] | [真实日期或确认条件] |

## 3. 每页简报模板

```markdown
### [页ID]：[主任务/页面类型]
- 场景与获批框架位置：[混合稿逐页具体标场景]
- 标题：[观点/明确假设/准确功能标题]
- 阅读任务：[理解/比較/监督/讨论/决定；无需强写客户决策]
- 核心观点和成熟度：[事实/测算/假设/示意]
- 主表达：[趋势/对标表/桥接/关系图/文字及理由]
- 证据模块：[模块ID→形式→支持哪条观点/反证/口径/风险/动作]
- 有效内容：[事实与推理，覆盖关键比较和不利证据]
- 关系与连接：[并列/依赖/分解/因果假设等；组合模块各自语义]
- 单位/期间/分母/工况：[每模块口径；差异显著说明]
- 图标意图：[对象→辨识价值→家族/位置→授权来源；或省略理由]
- 几何：[有数量含义的依据；定性等大示意不按比例]
- 关键边界：[假设、替代解释、否证条件、风险与缺口]
- 版式契约：[阅读顺序、字体/字号层级、框内边距、图表标签安全区]
- 来源与支撑索引：[可定位资料/日期/版本/同稿页或问题ID]
- 工程验收：[实际渲染页/对象ID、完整文本核对、溢出/裁切/遮挡/字体；未做写待验收]
```

内容起草不提前写“渲染通过”。需要机器规划检查用`templates/slide-brief.example.json`（Proposal）或`internal-report.example.json`（内部）；内部可用`reader_task`，旧`reader_decision`字段兼容。2.1增加场景/阅读方式、布局政策及模块支持关系，2.0仍可校验但不提供新字段检查。

## 4. Proposal序列

| 内容段 | 页面任务 | 可用表达 |
|---|---|---|
| 封面/摘要 | 客户目标、需求/路径/相关胜任 | 极简封面、摘要与支撑 |
| 背景目标 | 相关情境、困难和范围 | 事实—挑战—目标 |
| 问题树 | 研究要回答什么 | 边界明确的拆解 |
| 初步思考 | 假设和支撑/冲突/验证 | 证据面板、图表或对标 |
| 方法/工作/交付 | 如何研究、资源依赖与验收 | 工作流/甘特+交付物表 |
| 团队经验/商务 | 相关能力和报价/边界 | 已核实案例、职责、条款或待确认 |

六项覆盖可合并，摘要按任务配置，不强制每章过渡或三子点。

## 5. 内部汇报序列

内部领导/投资部依获批框架，设置执行摘要、实质章节的观点与证据/反证、章级小结、建议/关注/待讨论及同稿详细支撑。进度稿保留相对承诺的差距与风险，研讨稿保留替代解释和部门责任边界。多模块设计见`internal-executive-reporting.md`与`composite-visual-evidence.md`。

## 6. 工程验收记录

对实际交付文件记录渲染工具/环境、字体/替代、文件版本或哈希、页/对象ID及四边/尾字/图表标签/单元格/遮挡检查；修复后重验受影响页。布局脚本需要真实测量/审阅记录，`layout-metrics.example.json`为合成测试，不是此报告的测量结果。
