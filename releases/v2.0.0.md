# v2.0.0 升级说明 / Release Notes

**日期 / Date：2026-11-18**

## 中文

### 为什么升级

原Skill擅长描述咨询页面类型，但还不足以解释“面对不同业务内容，为什么选某种图形、何时加入商务扁平化图标”。本版吸收用户新增的图标、人物和场景素材，以及High Profile Proposal教学要求，将视觉表达提升为结构化思考的一部分，而不是装饰模板库。

### 关键变化

| 原逻辑 | v2.0.0逻辑 |
|---|---|
| 页面类型→套结构 | 客户要做的判断→内容关系→主视觉结构 |
| 图标作为模板组件 | 图标按需识别实体，箭头/树/矩阵表达关系 |
| 每步配图标 | 图标有识别价值才用，数据/条款页允许不用 |
| 方案、计划、团队分散 | 问题树与假设、方法、Owner、交付物及检查点闭环 |
| 强制字数、密度、字体 | 根据读者、材料性质与可读性调节 |
| 量化表达优先但易填假数 | 可核实数字才量化，未知写缺口/假设/验证路径 |

Proposal新增明确六要素：背景目标、关键问题、行业/公司初步思考、工作计划与交付物、相关经验与团队、商务条款。强调定制客户语境，相关性高于资历堆砌；样例交付物应管理预期，工作流可以并行而不能脱离资源约束。

### 文件与迁移

替换`SKILL.md`和更新后的参考目录，同时保留新增`scripts/`与`templates/`。旧提示“按麦肯锡风格做Proposal”仍可触发；更推荐增加读者决策、证据状态和图标使用目的。过去仅记录标题/页型/要点的大纲应补内容关系、视觉单元、图标意图或无图标理由、单位/几何、来源和问题—工作流映射。

仓库README/CHANGELOG/release notes面向用户，Agent按需读取核心与参考，不要求每次加载全部仓库文档。

### 验证与边界

发布前运行Skill结构校验、JSON示例校验与脚本回归，并审查引用路径与来源说明。简报校验器只检查声明结构；不能保证市场事实正确、MECE成立、PPT排版完美或图标许可完整。实际制作仍需证据核查与页面审阅。

本版没有开发Web产品，没有发布用户原始图标全集，也没有新增可直接复用的原始PPTX模板包。技能规则能够指导素材选择；真正使用某个图标仍需取得可用素材并检查授权。

## English

### Rationale

The baseline described common consulting slide types but did not sufficiently explain why a particular visual structure or icon should be selected for a given business message. Version 2 makes visual encoding part of structured reasoning, informed by newly supplied business-icon collections and high-profile proposal training.

### Main changes

Start with the reader's decision, identify the relationship, select the primary visual unit, then add flat business icons only for useful entity recognition. Arrows, trees and matrices express relationships; icons do not prove causality, represent unverified quantities or identify real people. No-icon data and commercial pages are valid.

Link project objectives, key questions, initial hypotheses, methods, work streams, owners, deliverables, client inputs and checkpoints. Preserve the three persuasion goals without forcing exactly three subpoints. Replace rigid length, density and font rules with audience-specific readability. Quantify only with verifiable evidence or explicit modeled assumptions.

### Migration

Replace the core and updated references, and retain the new scripts and templates. Existing style-based prompts remain usable. Planning outlines should add relationship semantics, icon intent or omission rationale, metric and geometry declarations, sources and question-to-workstream mapping. Repository user documentation is separate from the agent's progressively loaded references.

### Validation and limitations

The release is checked with the skill validator, planning example and regression tests plus source/path review. These checks do not establish factual accuracy, true MECE completeness, licensing, visual consistency or actual slide editability. Real deck creation still requires host tools, evidence review and layout inspection.

No web product, proprietary icon-library redistribution or new ready-made PPTX template pack is included. The release publishes reusable rules, planning examples and scripts only.
