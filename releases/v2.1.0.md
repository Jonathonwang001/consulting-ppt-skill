# v2.1.0 升级说明 / Release Notes

日期 / Date：2026-11-18

## 中文

### 升级原因

用户实际使用反馈要求补齐内部汇报、有效深度与排版底线。v2.0已有高管报告入口和人工溢出检查，但主流程偏对外Proposal，“唯一主关系”措辞偏严，工程验收颗粒度不足。本版保留原Proposal、图标和咨询框架，将场景路由与工程质量分开。

### 主要变化

| 项目 | 新行为 |
|---|---|
| 读者场景 | 对外Proposal、内部领导汇报、内部工作讨论、混合稿明确路由 |
| 内容组织 | 按理解/比较/监督/讨论/决定任务保留有效证据深度；不制造批准请求 |
| 内容取舍 | 淘汰无支撑重复，保留事实、同业、机制、反证、风险、口径及边界 |
| 组合视觉 | 一个主阅读任务可用多个协调结构/图表模块，说明证据贡献与连接口径 |
| 工程硬门槛 | 完整文本、四边无溢出、图表安全区、无非预期裁切/遮挡、字体正确；失败修复重渲染 |
| 模板与完整性 | 领导批准框架/样例优先，一个完整主稿含摘要、章级小结与详细支撑 |
| 工具 | 规划JSON2.1与内部示例；新增布局指标契约/检查器及合成测试 |

15字、60%面积和强制衬线不恢复为普遍配额。字体角色、项目字号、网格、行距、内边距与真实可读性仍需严格执行，零溢出不可按场景降低。

### 迁移

更新核心、参考、scripts和templates。2.0规划JSON保持兼容；2.1增加scenario、audience、reader_task、reading_mode、layout_contract和evidence_modules，内部进度页用action_tracking，纯内部诊断无需客户工作流。外部work_plan仍要求question_workstream_map闭环。旧reader_decision字段兼容，内部可使用reader_task。

### 校验与边界

发布前运行Skill结构校验、内外规划示例及回归、布局检查器回归和合成输入正反流程，并做独立QA。规划只验证声明结构；布局只核查提交bbox与审阅字段，不渲染PPTX、不测真实字形、不证明来源或审阅真实性。合成样例不得作为真实稿通过，最终文件必须逐页渲染核对。

本任务没有新建演示文稿、在线产品或新增原图标/模板包，没有认证任何真实PPT布局；用户截图中的dict-repo和85/85回归尚未在本任务接入验证。双语README/About/Changelog继续维护，旧v2.0.0版本不覆盖。

## English

### Rationale and changes

Version 2.0 already mentioned executive reports and rendering overflow review, but generalized external proposal planning too broadly. Version 2.1 makes audience-scenario routing explicit, preserves effective content depth and counterevidence, permits coordinated multi-module visual evidence, and specifies release-blocking text, chart-label, clipping, font and layout checks.

Internal reports match understanding, comparing, monitoring, discussing or deciding tasks without inventing approvals or sales credentials. Reuse leadership-approved references, retain important risks and assumptions, and deliver one complete main artifact with executive/chapter summaries and detailed support. Proposals retain their six content areas and question-to-workstream traceability.

### Migration and boundaries

Planning schema 2.0 remains compatible. Schema 2.1 adds scene, audience, reader task, reading mode, layout contract and evidence modules; internal progress pages use action tracking, while external work plans still require the proposal map. The legacy reader_decision field remains supported.

The planning linter checks declarations. The new layout checker consumes declared pixel bounds and manual-review fields; it does not render PPTX, measure glyphs, verify provenance or certify text completeness. Synthetic regression fixtures never constitute real-slide acceptance. Final artifacts require credible rendering and complete page review. Universal word-count, 60% area and serif quotas remain removed without weakening engineering gates.

No deck, web product, proprietary icon/template redistribution or actual-slide layout certification is included. An external dictionary repository and the screenshot's 85/85 results were not accessed or verified in this update. Bilingual user documentation is maintained and the previous release remains intact.
